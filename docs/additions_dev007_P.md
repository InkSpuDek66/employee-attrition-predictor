## หลัง pull เพื่อนต้อง

1. **รันไฟล์ schema ซ้ำ** 1 ครั้ง (รันซ้ำได้ ข้อมูลเดิมไม่หาย):
   `docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U attrition -d attrition < docker/postgres/init/02-app-schema.sql`
2. **แก้ `MODEL_URI` เป็น `/2` ถ้ายังไม่ได้แก้**: ใน `.env` ของตัวเอง เปลี่ยน `models:/attrition-xgboost-P/1` เป็น `models:/attrition-xgboost-P/2` แล้ว restart backend
3. **ปรับเทียบใหม่** ในหน้า "ปรับเทียบโมเดล" (login ด้วยบัญชี admin) เพราะค่าปรับเทียบผูกกับเวอร์ชันโมเดล ของ v1 ใช้กับ v2 ไม่ได้ ทดลองด้วยปุ่ม "ข้อมูลทดลอง 300 คน" ได้

ถ้าไม่รันข้อ 1 หน้าเว็บยังใช้ได้ แต่ไม่มีชื่อ/แผนกจริงขึ้น บริษัทใหม่ (`newco_demo`) ยังไม่มีในตาราง จึงนำเข้าไม่ได้ และการนำเข้าที่มีคอลัมน์ใหม่จะได้ข้อความให้อัปเดต schema

## 1. โมเดล v2: ไม่ใช้เพศและสถานภาพสมรส

- `src/train.py` ตัด `Gender` และ `MaritalStatus` (รวม one-hot) ก่อนเทรน (`EXCLUDED`) แต่ข้อมูลที่คลีนแล้วยังมีคอลัมน์เหล่านี้ ไว้ตรวจ Fairness (README 6.4)
- register เป็น `attrition-xgboost-P` v2 บน DagsHub แล้ว แอปใช้ v2 เป็นค่าเริ่มต้น (`backend/model_store.py`, `.env.example`, CI)
- เทียบกับ v1 ด้วย split / hyperparameter / จำนวน thread เดียวกัน:

  | | v1 (50 ฟีเจอร์) | v2 (46 ฟีเจอร์) |
  | :--- | :--- | :--- |
  | CV AUC (5 fold × 3 รอบ) | 0.827 ± 0.029 | 0.826 ± 0.030 |
  | Recall@top20% | 0.596 | 0.596 |
  | test ROC AUC (294 คน) | 0.814 (0.734–0.884) | 0.792 (0.708–0.866) |
  | test PR-AUC | 0.609 | 0.572 |

  ค่าที่ train.py บันทึกตอน register v2: test AUC 0.792, CV AUC 0.832 ± 0.029
- ตรวจ proxy: ใช้ฟีเจอร์ที่เหลือเดาเพศได้แค่ AUC 0.529 (แทบเดาไม่ได้) จึงตัดเพศแล้วได้ผลจริง ส่วนอายุยังใช้ต่อ เพราะอายุงานรวม (สัมพันธ์ 0.68) ระดับตำแหน่ง (0.51) และเงินเดือน (0.50) เดาได้ว่าใครอายุต่ำกว่า 30 ด้วย AUC 0.857 ตัดคอลัมน์อายุออกจึงไม่ได้ทำให้เป็นธรรมขึ้นจริง
- ระดับตำแหน่งใช้ต่อได้ เพราะเป็นเหตุผลเรื่องงาน (อัตราลาออกจริง ระดับ 1 = 26.3%, ระดับ 4 = 4.7%)
- ค้าง: ตัวเลขในรายงาน/สไลด์ยังเป็นของ v1 (AUC 0.81) ทีมต้องตัดสินใจว่าจะรายงาน v2 หรือทั้งสองเวอร์ชัน และ `src/predict_demo.py`, `src/shap_explain.py` ยังโหลด v1 (สคริปต์วิเคราะห์ ไม่กระทบเว็บ)

## 2. แยกข้อมูลตามบริษัท (tenant)

ก่อนหน้านี้ backend อ่านพนักงานของ `ibm_demo` ตายตัว ข้อมูลที่บริษัทนำเข้าจึงปนกับ IBM และรหัสซ้ำเขียนทับคนของ IBM ได้ ตอนนี้:

- `model_store` อ่านพนักงาน ฟีเจอร์ และ cache แยกตาม `tenant_id` ของผู้ login (`raw_employees(tenant)`, `employee_features(tenant)`, `employee_record(id, tenant)`)
- `/shap`, `/predict`, `/whatif`, `/financial-impact`, `/company-summary*` หาพนักงานเฉพาะในบริษัทของผู้ใช้ (พนักงานของบริษัทอื่น = 404)
- ข้อมูลอ้างอิงตอนแปลงฟีเจอร์ (one-hot ให้ครบหมวด) ใช้ CSV ของ IBM เสมอ (`reference_employees()`) ไม่ขึ้นกับบริษัท ลบ IBM ออกจากบริษัทเดโมก็ไม่กระทบการคำนวณของบริษัทอื่น
- `batch_score` คำนวณทีละบริษัทหลังนำเข้า/ปรับเทียบ รันจาก command line = ทุกบริษัทที่มีพนักงาน
- บริษัทที่ยังไม่มีพนักงาน: `/company-summary` ตอบ `n_employees: 0` หน้าภาพรวมแสดงผู้ช่วยพร้อมปุ่ม "ไปนำเข้าข้อมูล"
- บริษัททดลองที่สอง `newco_demo` ("บริษัทตัวอย่าง (เริ่มจากว่าง)") บัญชี `newco_admin` / `newco-admin-1234` และ `newco_hr` / `newco-hr-1234` (แสดงในกล่องบัญชีทดลองหน้า login)
- รหัสพนักงานซ้ำกันได้ระหว่างบริษัท (คีย์ของตารางคือ `tenant_id` + `employee_id` อยู่แล้ว)
- ไม่ตั้ง `DATABASE_URL` = มีข้อมูลเฉพาะบริษัทเดโม (CSV) บริษัทอื่นว่าง และนำเข้าไม่ได้
- ponytail: ข้อมูลบริษัทไหนเปลี่ยน ล้าง cache ทุกบริษัท (ง่ายและถูกเสมอ) แยกล้างรายบริษัทเมื่อมีหลายบริษัทจริงจนช้า

## 3. ข้อมูลที่บริษัทนำเข้า

| ช่องในไฟล์นำเข้า | สถานะ | ใช้ทำอะไร |
| :--- | :--- | :--- |
| ชื่อ-นามสกุล | ใหม่ ไม่บังคับ ≤ 100 ตัวอักษร | แสดงผลเท่านั้น ("ชื่อ · #รหัส") ไม่เข้าโมเดล |
| แผนก | เปลี่ยนความหมาย: ชื่อแผนกจริงของบริษัท | แสดงผล + แยกแผนกในหน้าภาพรวม |
| กลุ่มแผนก (ให้โมเดล) | ใหม่ (Sales / Research & Development / Human Resources หรือ ฝ่ายขาย / ฝ่ายวิจัยและพัฒนา / ฝ่ายบุคคล) | ใช้คำนวณ เว้นว่างได้ถ้า "แผนก" ตรงกับกลุ่ม |
| ตำแหน่งงาน | เปลี่ยนความหมาย: ชื่อตำแหน่งจริง | แสดงผล |
| กลุ่มตำแหน่ง (ให้โมเดล) | ใหม่ (9 ตำแหน่งของ IBM ดูชีต "ตัวเลือก") | ใช้คำนวณ เว้นว่างได้ถ้า "ตำแหน่งงาน" ตรงกับกลุ่ม |
| เพศ | เปลี่ยนเป็นไม่บังคับ | ไม่ใช้คำนวณ (โมเดล v2) เก็บไว้ตรวจ Fairness |
| เข้าออฟฟิศ (วัน/สัปดาห์) | ใหม่ ไม่บังคับ (ว่าง = 5) | ปรับระยะทางจากบ้านก่อนให้คะแนน: ระยะทาง × วัน / 5 (ไม่ต่ำกว่า 1 กม.) |
| ความพึงพอใจ 4 ช่อง + สมดุลงานกับชีวิต | เปลี่ยนเป็นไม่บังคับ (ว่าง = 3) | หน้าตรวจไฟล์เตือนจำนวนคนที่ถูกเติมค่า (DE-17) |
| ระดับตำแหน่ง | รับเป็นคำได้ (จูเนียร์ / พนักงานระดับกลาง / ซีเนียร์ / ผู้จัดการแผนก / ผู้จัดการใหญ่) หรือ 1–5 | ใช้คำนวณ |

- ไฟล์รุ่นก่อน (คอลัมน์ "แผนก"/"ตำแหน่งงาน" เป็นค่าของ IBM) และไฟล์ที่ใช้หัวคอลัมน์ภาษาอังกฤษแบบ IBM ยังใช้ได้
- ถ้า "แผนก" ไม่ตรงกับกลุ่มและไม่ได้กรอกกลุ่ม หน้าตรวจไฟล์บอกเป็นรายแถวว่าต้องกรอกช่องกลุ่ม
- นำเข้าซ้ำด้วยไฟล์ที่ไม่มีคอลัมน์ชื่อ/แผนกจริง ค่าเดิมใน DB ไม่หาย (บันทึกเฉพาะคอลัมน์ที่มีในไฟล์)
- รหัสพนักงาน = รหัสของบริษัท ระบบไม่ออกรหัสให้เอง: รหัสใหม่ = เพิ่มคน, รหัสที่มีอยู่แล้ว = อัปเดตคนเดิม (นำเข้าไฟล์เดือนใหม่แล้วคนเดิมไม่ซ้ำเป็นสองคน)
- ตัวเลือก "ไฟล์นี้คือพนักงานทั้งหมดตอนนี้" (admin, `full_roster`): คนที่ไม่อยู่ในไฟล์ถูกบันทึกว่าออกแล้ว (`employees.left_at` = วันนี้) ไม่ลบแถว ไม่นับในภาพรวม/SHAP/What-if ถ้านำเข้ารหัสนั้นอีก = กลับมาเป็นพนักงานปัจจุบัน
- หน้าตรวจไฟล์บอกก่อนกดบันทึกว่า "เพิ่มใหม่ X คน · อัปเดต Y คน · บันทึกว่าออกแล้ว Z คน" (`n_new`, `n_update`, `n_leaving`) และเตือนเมื่อจะบันทึกว่าออกเกินครึ่งของพนักงานปัจจุบัน (น่าจะเลือกไฟล์ผิด เช่น ไฟล์แผนกเดียว)
- ชื่อ / แผนกจริง / ตำแหน่งจริงอ่านแยกด้วย `db.employee_labels()` ไม่อยู่ใน `read_employees()` จึงไม่หลุดเข้าโมเดล, `/predict` หรือ `/whatif`

## 4. ปรับเทียบโมเดล (หน้า admin)

- หน้า "ปรับเทียบโมเดล" อัปโหลดไฟล์พนักงานในอดีตพร้อมผลลาออกจริง (Platt / isotonic) มีประวัติ ยกเลิกได้ และกราฟสูตรแปลงคะแนน (เส้นสูตร, เส้น "ถ้าไม่ปรับ", จุดอัตราลาออกจริงตามช่วงคะแนน)
- ผลปรับเทียบเปลี่ยนคะแนนทุกหน้า (ภาพรวม SHAP What-if ระดับความเสี่ยง ค่าเฉลี่ยบริษัท) ไม่เปลี่ยนตัวโมเดลและปัจจัยใน SHAP
- "ข้อมูลทดลอง 300 คน" (`/recalibrate/template?demo=true`) เปลี่ยนจากพนักงาน IBM (ที่โมเดลเคยเห็นตอนเทรน) เป็นพนักงานจำลอง:
  - รหัส 1–300 เรียงต่อกัน มีชื่อ-นามสกุลจำลองตามเพศ (ไม่ใช้คำนวณ) ตั้งต้นจากคน IBM แบบสุ่มแล้วสุ่มปรับอายุ เงินเดือน ระยะทาง ความพึงพอใจ OT ฯลฯ (แผนก/ตำแหน่ง/ระดับยังคู่กันแบบสมเหตุสมผล)
  - ผลลาออกสุ่มจากคะแนนโมเดลที่ลดลง (logit − 1.0) = "บริษัทที่ลาออกน้อยกว่าที่โมเดลคิด" ได้อัตราลาออกราว 24%
  - seed คงที่ ดาวน์โหลดกี่ครั้งก็ได้ไฟล์เดิม ผ่านการตรวจไฟล์ครบ 300 แถว

## 5. API ที่เปลี่ยน (เพิ่มฟิลด์ ไม่ลบของเดิม)

| Endpoint | เพิ่ม |
| :--- | :--- |
| `GET /shap/{id}` | `name`, `department`, `job_role` (ชื่อจริงของบริษัท ไม่มี = ชื่อกลุ่มของโมเดล), `commute` (ระยะทางจริงกับค่าที่ใช้หลังปรับ WFH) |
| `GET /company-summary/top-employees` | `name`; `department` / `job_role` เป็นชื่อจริงของบริษัท |
| `GET /company-summary`, `/departments` | แยกแผนกตามชื่อแผนกจริง (`?department=ฝ่ายการเงิน` ได้) บริษัทว่าง = `n_employees: 0` |
| `POST /employees/validate`, `/employees/import` | form `full_roster` (true/false); ผลมี `n_new`, `n_update`, `n_leaving`; import มี `saved_names` (ชื่อของคนที่เพิ่งบันทึก) |
| `GET /employees/template` | คอลัมน์ใหม่ตามหัวข้อ 3 + ชีต "ตัวเลือก" มีกลุ่มแผนก |
| `POST /recalibrate*` | ผลมี `curve` (51 จุด) และ `bins` (อัตราลาออกจริงต่อช่วงคะแนน 0.1) สำหรับกราฟ |

## 6. Database (`02-app-schema.sql`)

- `employees.left_at` เริ่มใช้งาน: ไม่ว่าง = บันทึกว่าออกแล้ว `read_employees()` อ่านเฉพาะคนที่ว่าง (พนักงานปัจจุบัน)
- `employees`: เพิ่ม `office_days_per_week` (0–5, ค่าเริ่มต้น 5), `full_name`, `department_name`, `job_title` (text ≤ 100 ว่างได้), `gender` ว่างได้
- `tenants`: เพิ่มแถว `newco_demo`
- `company_risk_summary`: `department` เก็บชื่อแผนกจริงของบริษัท (บริษัทเดโม = ชื่อของ IBM เหมือนเดิม)
- ทุกการเปลี่ยนมี `ALTER ... IF NOT EXISTS` สำหรับ volume เดิม

## 7. หน้าเว็บ

- ธีมฟ้าพาสเทล (โหมดสว่าง/มืด), โลโก้ที่เปลี่ยนสีตามโหมด, หน้า login ใหม่ (มาสคอต จอย / กิต / ส้มฉุน / ปุกปุย, สลับโหมดได้, ไม่ต้องเลื่อน)
- ภาพรวม: โดนัทสัดส่วนความเสี่ยง, วงกลมตัวย่อตำแหน่งหน้ารายชื่อ, มูลค่าความเสี่ยงแบบย่อ "~458 ล้านบาท" พร้อมปุ่ม "ดูจำนวนเต็ม", คำทักทายตามเวลา, หน้าว่างของบริษัทใหม่, CSV มีคอลัมน์ชื่อ
- SHAP: 2 คอลัมน์ การ์ดคะแนนล็อกขวาเหมือน What-if (ชื่อ ตำแหน่ง แผนก), ขีดค่าเฉลี่ยบริษัทบนเกจ, กล่องรายละเอียดตอนชี้แท่งกราฟ, พิมพ์ / บันทึก PDF เป็นรายงานรายคน
- What-if (ร่วมกับ Saphondanai): 2 คอลัมน์, ข้อความเด้งเมื่อระดับความเสี่ยงเปลี่ยน, ระดับตำแหน่งเป็นคำ, ตัวเลือกเข้าออฟฟิศ / preset "ให้ WFH 3 วัน", คำอธิบายช่องจากแบบสำรวจ
- ทั่วไป: "ดูล่าสุด" 5 คนใต้ช่องรหัส, ช่องรหัสลอยตามมุมขวาบนเมื่อเลื่อนลง (จอใหญ่), ปุ่มกลับขึ้นด้านบน (มือถือ), ตัวโหลดเป็นมาสคอตกระโดด + จุดเด้ง, แอนิเมชันกราฟ/ตัวเลข (ปิดเองเมื่อตั้งลดการเคลื่อนไหว), สี selection / focus / scrollbar ตามธีม
- แก้บัค: แถบคะแนนด้านล่างของ What-if บนมือถือไม่ติดขอบจอ (แอนิเมชัน `fade-up` ค้าง transform)

## 8. ความปลอดภัยและข้อมูลส่วนบุคคล

- CSV ที่ดาวน์โหลด: ช่องข้อความที่ขึ้นต้นด้วย `=` `+` `-` `@` tab CR ใส่ `'` นำหน้า กันสูตร Excel (`csvCell` ใน `theme.js`)

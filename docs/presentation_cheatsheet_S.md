# สรุปโปรเจคสำหรับเตรียมนำเสนอ (Saphondanai)

> โน้ตทบทวนก่อนพรีเซนต์ ตัวเลขทั้งหมดมาจากโมเดลสุดท้าย `attrition-xgboost-P` v1 วัดบนชุด test 294 คน (ลาออกจริง 47 คน) รายละเอียดเต็มอยู่ที่ [report_business_logic_draft_S.md](report_business_logic_draft_S.md)

## 1. โปรเจคนี้คืออะไร

เว็บสำหรับฝ่ายบุคคล (HR) ที่ทำนายว่าพนักงานคนไหนมีแนวโน้มลาออก บอกเหตุผล และคำนวณว่ารั้งเขาไว้คุ้มกว่าหาคนใหม่หรือเปล่า

เทียบง่ายๆ ได้กับเครื่องวัดไข้ แต่เครื่องนี้วัด "ความเสี่ยงลาออก" ออกมาเป็นคะแนน 0–1

## 2. ระบบทำงานยังไง

```
ข้อมูลพนักงาน → ทำความสะอาด + สร้างฟีเจอร์ → โมเดล XGBoost → API (FastAPI) → หน้าเว็บ (React)
```

1. ข้อมูล: ชุด IBM HR จาก Kaggle มีพนักงาน 1,470 คน ลาออก 16% เป็นข้อมูลสมมติ ไม่ใช่ของบริษัทจริง
2. เตรียมข้อมูล: ทำความสะอาด แล้วสร้างฟีเจอร์ใหม่ 3 ตัวที่ผ่านการคัดเลือก คือ OT×ระยะทางจากบ้าน (`OverTimeXDistance`), ความพึงพอใจเฉลี่ย (`AvgSatisfaction`) และสัดส่วนอายุงานในบริษัทต่ออายุงานทั้งหมด (`TenureRatio`)
3. โมเดล: XGBoost ให้คะแนนความเสี่ยงรายคน ทุกการทดลองบันทึกไว้ใน MLflow
4. หน้าเว็บมี 5 แท็บ

| แท็บ | ใช้ทำอะไร |
| :--- | :--- |
| ภาพรวมบริษัท | เสี่ยงกี่คน แผนกไหนหนักสุด ปัจจัยหลักพร้อมคำแนะนำ |
| SHAP Viewer | ทำไมคนนี้ได้คะแนนสูง เช่น เพราะทำ OT เยอะ |
| What-if Simulator | ลองปรับเงื่อนไข เช่น ขึ้นเงินเดือน 10% แล้วดูคะแนนใหม่ + ต้นทุน Retain vs Replace |
| ปรับเทียบโมเดล | ปรับสเกลคะแนนให้เข้ากับข้อมูลของบริษัทนั้น (เฉพาะผู้ดูแลระบบ) |
| นำเข้าข้อมูล | อัปโหลดไฟล์ Excel รายชื่อพนักงาน |

## 3. ตัวเลขที่ต้องจำ

## 4. ส่วนที่ Saphondanai ทำ

1. ตั้ง MLflow ให้ทีม ทั้งบน DagsHub และ Docker ต้องเสร็จก่อนทีมจึงเริ่มเทรนได้
2. เทรนและจูน XGBoost คู่กับ Puripat ฝั่งเราจูนด้วย PR-AUC เพราะคนลาออกมีน้อย ผลออกมาใกล้กันมาก (ต่างกันไม่เกิน 0.017 อยู่ในระดับ noise) ทีมเลยเลือกโมเดลของ Puripat
3. Financial Impact: เทียบต้นทุนรั้งไว้กับหาคนใหม่ ค่าชดเชยอิงมาตรา 118 กฎหมายแรงงานไทย
4. สรุปภาพรวมบริษัท: จัดอันดับปัจจัยเสี่ยงรายแผนก พร้อมคำแนะนำเชิงนโยบาย
5. API `/predict`, `/whatif` และหน้า What-if Simulator

หัวข้อสไลด์ Data Gate ตาม [TASKS.md](../TASKS.md) คือ "Modeling Results & MLflow" (2–3 แผ่น) ใช้ข้อ 1, 2 และตารางในหัวข้อ 3 ได้เลย

## 5. Accuracy คืออะไร และทำไมไม่ใช้

Accuracy คือสัดส่วนที่ทายถูกจากทั้งหมด

```
Accuracy = จำนวนที่ทายถูก ÷ จำนวนทั้งหมด
```

ชุด test มี 294 คน ลาออกจริง 47 คน อยู่ต่อ 247 คน ถ้ามีโมเดลขี้เกียจที่ทายทุกคนว่า "ไม่ลาออก" โดยไม่ดูข้อมูลเลย

- ทายถูก 247 คน ทายผิด 47 คน
- Accuracy = 247 ÷ 294 = 84%

ตัวเลขดูดี แต่จับคนลาออกไม่ได้สักคน ซึ่งเป็นสิ่งเดียวที่ HR ต้องการ กลุ่มที่สนใจมีน้อย (16%) Accuracy เลยหลอกตา โปรเจคนี้จึงวัดด้วย AUC กับ Recall แทน

| ตัวชี้วัด | โมเดลเรา | โมเดลขี้เกียจ |
| :--- | ---: | ---: |
| AUC | 0.81 | 0.5 |
| Recall@top20% | ~60% | 0% |

## 6. Recall กับ Precision (ตัวอย่างจากโปรเจค)

ถ้าตัดที่คะแนน 0.5 โมเดลเตือน 76 คน ลาออกจริง 30 คน จากคนลาออกทั้งหมด 47 คน

- Recall = 30 ÷ 47 = 64% คือคนที่ลาออกจริง จับได้เกินครึ่ง
- Precision = 30 ÷ 76 = 39% คือในคนที่เตือน มีเตือนผิดอยู่บ้าง

## 7. ศัพท์ที่ต้องจำ (พร้อมคำอ่าน)

### 7.1 ต้องจำ (ได้พูดหรือโดนถามแน่)

| ศัพท์ | อ่านว่า | ความหมาย |
| :--- | :--- | :--- |
| Model | โม-เดล | โปรแกรมที่เรียนรูปแบบจากข้อมูลเก่า แล้วเอาไปทายข้อมูลใหม่ |
| Feature | ฟี-เจอร์ | ข้อมูลแต่ละอย่างที่ป้อนให้โมเดล เช่น อายุ เงินเดือน ทำ OT ไหม |
| XGBoost | เอ็กซ์-จี-บูสต์ | โมเดลที่เราใช้ สร้างต้นไม้ตัดสินใจทีละต้น ต้นใหม่แก้จุดที่ต้นก่อนทายผิด |
| Train / Test | เทรน / เทสต์ | แบ่งข้อมูล 80% ให้โมเดลเรียน อีก 20% เก็บไว้สอบ (ข้อสอบต้องไม่เคยเห็น) |
| Risk score | ริสก์-สกอร์ | คะแนนความเสี่ยงลาออก 0–1 ยิ่งสูงยิ่งเสี่ยง |
| Risk band | ริสก์-แบนด์ | แบ่งคะแนนเป็น สูง (≥0.7) กลาง (0.4–0.7) ต่ำ (<0.4) |
| Class imbalance | คลาส-อิม-แบ-แลนซ์ | ข้อมูลไม่สมดุล คนลาออกมีแค่ 16% |
| Accuracy | แอค-คิว-เร-ซี่ | ทายถูกกี่ % ของทั้งหมด (เราไม่ใช้ ดูหัวข้อ 5) |
| AUC | เอ-ยู-ซี | แยกคนลาออกออกจากคนอยู่ต่อได้ดีแค่ไหน 0.5 = เดาสุ่ม, 1 = สมบูรณ์แบบ เราได้ 0.81 |
| Recall | รี-คอล | ในคนที่ลาออกจริง โมเดลจับได้กี่ % |
| Precision | พรี-ซิ-ชั่น | ในคนที่โมเดลเตือน ลาออกจริงกี่ % |
| Recall@top20% | รี-คอล แอท ท็อป ทเวน-ตี้ เปอร์-เซ็นต์ | ดูแล 20% ที่คะแนนสูงสุด ครอบคลุมคนลาออกจริงกี่ % เราได้ ~60% |
| SHAP | แชป | บอกว่าแต่ละปัจจัยดันคะแนนของคนคนหนึ่งไปทางลาออก (ค่าบวก) หรือทางอยู่ต่อ (ค่าลบ) มากแค่ไหน |
| MLflow | เอ็ม-แอล-โฟลว์ | สมุดบันทึกผลการทดลองทุกครั้ง และที่เก็บโมเดลตัวที่เลือกใช้ |
| What-if | วอท-อิฟ | ลองเปลี่ยนเงื่อนไขสมมติ แล้วดูว่าคะแนนเปลี่ยนเท่าไร |
| Financial Impact | ไฟ-แนน-เชียล อิม-แพ็กต์ | คำนวณว่ารั้งพนักงานไว้หรือหาคนใหม่ แบบไหนคุ้มกว่า |
| Retain / Replace | รี-เทน / รี-เพลส | รั้งไว้ / หาคนใหม่ |
| มาตรา 118 | มาตรา หนึ่ง-ร้อย-สิบ-แปด | กฎหมายค่าชดเชย จ่ายเฉพาะตอนนายจ้างเลิกจ้าง ไม่จ่ายถ้าลาออกเอง |

| ศัพท์ | อ่านว่า | ความหมาย |
| :--- | :--- | :--- |

## 8. วิธีอ่านตัวเลขตอนพูด

- AUC 0.81 อ่านว่า "เอ-ยู-ซี ศูนย์จุดแปดหนึ่ง"
- Recall@top20% ประมาณ 60% อ่านว่า "รีคอลที่ท็อปยี่สิบเปอร์เซ็นต์ ประมาณหกสิบเปอร์เซ็นต์"
- ลาออก 16% อ่านว่า "อัตราลาออกสิบหกเปอร์เซ็นต์"

ตัวย่อส่วนใหญ่อ่านทีละตัว (เอ-ยู-ซี, เอ-พี-ไอ, ซี-ไอ) ยกเว้น SHAP ที่อ่านเป็นคำเดียวว่า "แชป"

## 9. คำถามที่น่าจะโดน

**ทำไมไม่ใช้ Accuracy?**

คนลาออกมีแค่ 16% ถ้าทายว่าไม่มีใครลาออกเลยก็ได้ 84% แล้ว แต่ใช้งานจริงไม่ได้ เราเลยวัดด้วย AUC กับ Recall ซึ่งดูว่าจับคนที่จะลาออกได้จริงหรือเปล่า

**ทำไมเลือก XGBoost ไม่ใช่ Ensemble ที่ F1 ดีกว่านิดหน่อย?**

Ensemble มี SVM อยู่ข้างใน ใช้ SHAP TreeExplainer อธิบายเหตุผลไม่ได้ และ HR ต้องรู้ว่า "ทำไม" ถึงเอาไปทำอะไรต่อได้

**ข้อมูลเป็นของบริษัทอเมริกา ใช้กับบริษัทไทยได้ไหม?**

วิธีการใช้ได้ แต่ความแม่นยังต้องพิสูจน์ด้วยข้อมูลจริงของบริษัทไทย ส่วนที่ปรับให้เข้ากับไทยแล้วคือปุ่มปรับเทียบโมเดล (recalibrate) ค่าชดเชยตามมาตรา 118 และคำแนะนำแบบไทย เช่น แนะนำกองทุนสำรองเลี้ยงชีพแทนสิทธิ์ซื้อหุ้น

**ค่าชดเชยรวมในต้นทุนการลาออกเสมอไหม?**

ไม่ ค่าเริ่มต้นไม่รวม เพราะมาตรา 118 จ่ายเฉพาะตอนนายจ้างเลิกจ้าง คนที่ลาออกเองไม่ได้ค่าชดเชย มีตัวเลือก `include_severance` ไว้ใช้กรณีบริษัทพิจารณาเลิกจ้าง

**ทำไมโมเดลของ Saphondanai กับ Puripat ผลต่างกันนิดเดียว ถึงเลือกของ Puripat?**

ต่างกันไม่เกิน 0.017 ซึ่งอยู่ในระดับ noise เพราะชุด test มีคนลาออกแค่ 47 คน สรุปไม่ได้ว่าตัวไหนดีกว่า ทีมเลือกของ Puripat ที่ test AUC (0.814 เทียบ 0.807) และ PR-AUC (0.609 เทียบ 0.592) สูงกว่าเล็กน้อย แล้ว register เป็น `attrition-xgboost-P` v1

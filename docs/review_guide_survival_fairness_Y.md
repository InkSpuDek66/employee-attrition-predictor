## ขั้นที่ 2: ตรวจวิธีทำ (ข้อละไม่กี่นาที)

### Survival Analysis (โน้ตบุ๊ก 08)
- [ ] **นิยามถูก:** duration = `YearsAtCompany`, event = ลาออก (1) คนที่ยังไม่ลาออกเป็น censored **ไม่ได้ถูกตัดทิ้ง** (ดูขั้นตอนที่ 1 ว่าใช้ครบ 1,470 คน)
- [ ] **ตารางรายปีรวมแล้วสมเหตุสมผล:** คอลัมน์ `at_risk` ลดลงทุกปี และปี 0 = 1,470 คน
- [ ] **ทิศทางตรงกับ EDA:** กลุ่มที่ EDA บอกว่าลาออกมาก (OT, อายุน้อย, ระดับ 1, ไม่มี stock option) เส้น KM ต้องตกเร็วกว่า และ HR ใน Cox ต้องมากกว่า 1 (หรือน้อยกว่า 1 สำหรับปัจจัยที่ช่วยให้อยู่)
- [ ] **การนับปีถูก:** `YearsAtCompany` คือปีที่ทำงานครบแล้ว คนที่มีค่า 1 ลาออกระหว่างปีที่ 2 ตาราง "อยู่ครบ n ปี" จึงต้องใช้ค่าบนเส้น KM ที่ t = n−1 (อ่านคำอธิบายในขั้นตอนที่ 2) ลองนับเองจากตารางรายปีว่า 32% กับ 43% มาจากไหน
- [ ] **เข้าใจว่าทำไมไม่ใส่** `YearsInCurrentRole`, `YearsWithCurrManager`, `YearsSinceLastPromotion`, `TotalWorkingYears` ใน Cox และทำไมใช้อายุตอนเข้างานแทนอายุปัจจุบัน (อ่านขั้นตอนที่ 5) ลองอธิบายด้วยคำพูดตัวเองได้ไหม
- [ ] **ข้อจำกัดเขียนครบ:** proportional hazards ไม่ผ่าน 6 ตัว, เรื่องคนโสดไม่มี stock option, ข้อมูล snapshot (DS-01), ปีเป็นจำนวนเต็ม, ผลเป็นความสัมพันธ์ไม่ใช่เหตุและผล

### Fairness Check (โน้ตบุ๊ก 09)
- [ ] **ไม่ได้วัดบนข้อมูลที่โมเดลเคยเห็น:** คะแนนมาจาก out-of-fold (ฟังก์ชัน `oof_scores`) และ `scale_pos_weight` คิดจากส่วนที่ใช้เทรนในแต่ละ fold เท่านั้น
- [ ] **ค่าโมเดลตรงกับของจริง:** `PARAMS` ในโน้ตบุ๊กตรงกับ `PARAMS` ใน [src/train.py](../src/train.py) ทุกตัว
- [ ] **ตัวเลขใกล้กับ DS-04** ใน [review Data Engineering](review_data_engineering_S.md) (ต่างกันเล็กน้อยได้ เพราะสุ่มแบ่ง fold ต่างกัน)
- [ ] **เข้าใจว่าทำไมใช้ TPR (equal opportunity) เป็นเกณฑ์หลัก** แทน "ถูกเตือนเท่ากัน" (อ่านส่วนหัวโน้ตบุ๊ก)
- [ ] **อ่าน CI ถูก:** อายุและสถานภาพ CI ไม่คร่อม 0 = ต่างกันจริง, เพศ CI เริ่มที่ 0.00 = อาจเป็นความบังเอิญ
- [ ] **ข้อเสนอเกณฑ์ TPR ratio ≥ 0.8:** เห็นด้วยไหม ถ้าไม่เห็นด้วย เสนอค่าอื่นพร้อมเหตุผล (ทีมต้องตัดสินใจเรื่องนี้ใน wk6–7 ตาม README 6.4)
- [ ] **ข้อความเตือนสำหรับหน้าเว็บ:** ภาษาเข้าใจง่ายสำหรับ HR ไหม ปรับคำได้เลย

## คำถามที่กรรมการน่าจะถาม (ฝึกตอบด้วยกัน)

1. **Survival Analysis ต่างจากโมเดล XGBoost ยังไง?**
   XGBoost ตอบว่า "เสี่ยงแค่ไหน" Survival ตอบว่า "ถ้าออก มักออกตอนไหน และกลุ่มไหนออกเร็วกว่า"
2. **ทำไมไม่เฉลี่ยอายุงานของคนที่ลาออกไปเลย?**
   คนที่ยังไม่ลาออก (84%) ก็ให้ข้อมูลว่า "อยู่มาได้อย่างน้อยเท่านี้" ถ้าตัดทิ้งจะสรุปว่าคนลาออกเร็วเกินจริง
3. **Hazard ratio 3.2 ของ OT แปลว่าอะไร?**
   ในทุกช่วงเวลา คนทำ OT มีโอกาสลาออกประมาณ 3 เท่าของคนไม่ทำ เมื่อปัจจัยอื่นเท่ากัน และ OT ผ่านสมมติฐาน proportional hazards จึงอ้างตัวเลขนี้ได้ (ปัจจัยที่ไม่ผ่าน ให้อ้างแค่ทิศทาง)
4. **โมเดลลำเอียงไหม?**
   ด้านเพศใกล้เคียงกัน แต่ด้านอายุและสถานภาพไม่เท่าเทียม คนอายุ 40 ขึ้นไปที่จะลาออก ระบบจับได้ไม่ถึงครึ่ง จึงต้องมีข้อความเตือนผู้ใช้
5. **ทำไมไม่ตัดอายุออกให้หายลำเอียง?**
   อายุเป็นปัจจัยสำคัญ และทดลองแล้วว่าตัดเพศหรือสถานภาพออกก็ไม่ทำให้ช่องว่างหาย แปลว่าความต่างมาจากข้อมูล ไม่ได้มาจากการที่โมเดลเห็นคอลัมน์นั้น
6. **ทำไมใช้ statsmodels ไม่ใช้ lifelines ตามแผน?**
   lifelines เวอร์ชันล่าสุดยังไม่รองรับ pandas 3 ที่โปรเจกต์ใช้ statsmodels ทำ Kaplan-Meier, log-rank และ Cox ได้ครบเหมือนกัน
